# 0.5.0 リリース

対象: [turbowarp-plus-editor#774](https://github.com/kubohiroya/turbowarp-plus-editor/issues/774) の受け入れ基準2（失敗した assertion ブロックの上に印が出る）。ブランチ: `chore/release/0.5.0`、base: `301a2ed`。

PR #11 で入れた、失敗した確かめるブロックへの印を配布版へ反映します。

- テスト実行画面が、結果の変わるたびに失敗した確かめるブロックの一覧を任意の `markFailures(marks)` でホストに渡す。理由の1行は `failureLabel(locale, record)` として公開する。
- `createTestRunEditor` が、表示中のコードで該当ブロックの輪郭を赤くし、「!」の印と理由のツールチップを付ける。ワークスペースはナビゲーションの口に足した任意の `workspace()` から受け取る。

公開 API は追加だけで、既存の呼び出し方は変わらないため minor を上げます。この候補は package.json と lockfile の版を 0.4.2 から 0.5.0 へ進め、この記録を足すだけです。

## 公開手順

1. 固定依存で `npm test` とヘッドレスの `npm run test:browser` を実行する。
2. PR の CI 確認後に Squash Merge し、マージコミットからビルド・pack して内容を確かめる。
3. `v0.5.0` タグをマージコミットに付けて push し、GitHub Release にアーカイブを添付する。同じアーカイブを npm CLI で `--access public --tag latest --ignore-scripts` により公開する。
4. registry のアーカイブの integrity と版を、添付したアーカイブと照合する。
5. 公開版で Editor の依存を固定し、`site/test-run/editor.ts` でワークスペースを渡す。

## 切り戻し

公開前はこの版変更を revert します。公開後は同じ npm 版を置き換えず、Editor の依存を 0.4.2 に戻します。Editor が `workspace()` を渡さなければ、印の処理は動きません。
