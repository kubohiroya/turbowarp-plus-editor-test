## 受け入れ基準・公開手順

1. 固定依存で`npm test`と通常のヘッドレス`npm run test:browser`を実行する。修正前の回帰失敗と、所有修正の単体22件・ブラウザー14件の結果は前提として保持し、リリース候補でも全件を確認する。
2. 清潔な候補コミットからビルド・packし、版、exportと型宣言、修正済みeditor-host、変更していないframeプロトコル、test／node_modulesの非同梱を確認する。`npm publish --dry-run`も確認する。
3. 外部操作の対象・文面を提示して承認後、push・PR作成・CI確認後のSquash Mergeを行う。マージコミットを取得し、同じ固定依存でビルド・packして候補アーカイブの展開内容と照合する。
4. 承認された場合だけ`v0.4.2`タグをマージコミットへ作成・pushし、GitHub Releaseへアーカイブを添付する。本リポジトリにRelease workflowはないため、検証した同じアーカイブをnpm CLIで`--access public --tag latest --ignore-scripts`により公開する。
5. GitHub添付とregistryのアーカイブを取得してバイト一致・integrity・版を確認する。Web認証が必要な場合はnpm CLIのTTY案内からOSの既定Chromeを開き、ユーザーの操作を待つ。
6. 公開された実integrityでEditor依存を固定し、そのEditor mainへDesktop rendererを固定・再検証する。製品の固定更新は別差分とする。

## 検証の範囲・切り戻し

所有修正だけの一時プレビューでは、実Desktop rendererで2フォルダの自動更新・停止／再開、不互換拒否と復旧、未保存編集保持、TypeScript診断、同じScratchテストの失敗→成功まで通っています。公開版0.4.2を採用した製品の結果とは区別し、採用後に再検証します。画面表示・OS入力・実Electronの起動は行いません。

公開前はこの版変更をrevertします。公開後は同じnpm版を置換せず、Editor依存とDesktop rendererを直前の検証済み固定へ戻して再ビルドします。修正が必要なら新しい版を公開し、作品と開発フォルダは保持します。
